# Restaurant Ops — 飲食店の売上集計・営業日報

売上CSVの確認・集計・日報作成を一つの画面で行う、ローカル実行型の業務改善デモです。
架空の喫茶店「こもれび」のデータを同梱しています。実店舗の情報は含みません。

## 解決したいこと

閉店後に、売上CSVを開き、日別・商品別に集計して、日報へ転記する作業を想定しました。
CSV取り込みから集計・日報の下書きまでをつなぎ、担当者は内容の確認と引き継ぎ事項の記入に集中できます。
飲食の勤務経験を出発点にした仮説であり、店舗への導入実績や削減時間の実測はありません。

## できること

- 売上CSVの取り込み（UTF-8 / 2MB / 10,000行まで）
- 必須項目、日付、整数範囲、重複の検証。不備があればファイル全体を不受理
- 日別・商品別集計、期間・商品名の絞り込み、同じ条件での商品別CSV出力
- 定型ルールによる日報の下書き、編集、保存、確定
- 売上が追加された下書きの再集計、古い画面からの上書き防止
- 確定済み日報のJSON出力（外部自動化へ接続するための素材）
- 取り込みの成功・失敗履歴

**日報作成は生成AIを呼び出しません。APIキー・有料AI契約なしで動きます。**
Makeへの送信は別途設定が必要です。この版はJSON出力までを実装しており、実際のMake接続を検証した作品とは表記しません。

## 起動（Windows）

Python 3.11以上が必要です。開発・テスト環境はWindows / Python 3.14です。

1. このフォルダーの `start.bat` をダブルクリックします。
2. 初回のみ専用の仮想環境にライブラリをインストールします。
3. ブラウザで <http://127.0.0.1:8000> を開きます。
4. 「CSV取り込み」→「サンプルデータを取り込む」を押します。
5. 終了は起動したターミナルで `Ctrl+C`。

手動の場合：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

macOS / Linuxでは仮想環境のPythonを `.venv/bin/python` に読み替えてください。
ポート8000が使用中なら `--port 8001` とし、ブラウザも8001へ変更します。
API仕様は起動後の `/docs` で確認できます。

作品紹介ページは起動後の <http://127.0.0.1:8000/portfolio> で表示できます。
`static/portfolio.html` を直接開いて紹介文を読むこともできます（アプリ操作にはサーバーの起動が必要です）。
GitHubや外部ホスティングへの公開はまだ行っていません。

## 3分で試す

1. サンプルを取り込む：35行・7営業日・5商品。
2. ダッシュボードで日別と商品別の売上を確認。日付で絞り込み、CSVを出力。
3. 同じサンプルを再度取り込み、重複が拒否されることを確認。
4. `samples/invalid-sales.csv` を取り込み、行番号付きのエラーを確認。
5. 営業日報で日付を選択し、下書きに引き継ぎ事項を追記して保存。
6. 内容を確認して確定し、JSONを保存。処理履歴も確認。

確定後の日報編集と同日の売上追加は、この版では禁止しています。試す日付を選んでから確定してください。
通常起動時は空のDBを作ります。サンプルの取り込みは任意です。

## 技術構成

| 層     | 使用技術                    | 選定理由                                     |
| ------ | --------------------------- | -------------------------------------------- |
| API    | Python / FastAPI / Pydantic | 検証とAPI仕様の明示                          |
| DB     | SQLite / SQL                | 外部DBなしで試せる・トランザクションを学べる |
| 画面   | HTML / CSS / JavaScript     | 小さな構成で全体を説明しやすい               |
| テスト | pytest / FastAPI TestClient | 異常系・データ整合性を自動確認               |

金額は浮動小数点ではなく整数の円として計算します。数量×単価の合計を売上とし、決済件数や客単価とは区別しています。
商品名は画面に `textContent` で挿入し、CSV出力では数式として解釈される先頭文字を無効化します。

```text
app/main.py           API・日報の状態変更
app/service.py        CSV検証・SQL・集計
static/               画面・スタイル・画面操作
samples/              正常・異常データ（すべて架空）
tests/                自動テスト
docs/                 設計、デモ手順、学習、Make連携の案
data/                 実行時DB（Git管理対象外）
```

## テスト

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

自動テストは一時DBを使うため、通常のアプリデータを書き換えません。
正常な集計、日付絞り込み、入力不備、文字コード、ファイルサイズ、重複、同時取り込み、永続化、日報確定、古い版からの上書き、CSV数式対策などを検証します。
検証記録は [docs/verification.md](docs/verification.md) を参照してください。

## この版の制約

- **個人PCでのデモ専用**。ログイン・権限管理は未実装です。`0.0.0.0`で公開したり、実際の顧客情報を扱ったりしないでください。
- 1店舗を想定。複数店舗、複数ユーザー、返品、値引き、税率計算、POS接続は未実装です。
- 日報の下書き本文は編集可能なため、集計値を書き換えることもできます。業務導入時は集計値と自由記述を分ける設計が必要です。
- 日報再集計では「【気づき・引き継ぎ】」以降を保持します。この見出しを削除すると保持できません。
- SQLiteを使用する小規模デモです。本番向けのバックアップ・監視・負荷試験は実施していません。
- Make連携、AI分析、公開Webデモ、デモ動画は未実装／未作成です。

## AI利用と制作経緯

この作品は、応募準備のために**Codexの支援で設計・コード生成・テスト・文書作成を行った学習用プロジェクト**です。
「すべて独力で実装した」「実務で導入した」とは表現しません。
応募者自身がコードを読み、手元で操作・修正・検証した内容を、面談で説明できる状態にすることを目的としています。
