# Make連携の設計案（未接続）

現在実装済みなのは、確定済み日報をJSONで出力するところまでです。
有料契約や外部APIへの送信は行っていません。以下は今後、Makeのテスト用環境で試すための設計案です。

## ペイロード

```json
{
  "event": "report.confirmed",
  "event_id": "report:2026-10-01:v3",
  "report": {
    "sold_on": "2026-10-01",
    "content": "営業日報の本文",
    "status": "confirmed",
    "version": 3,
    "updated_at": "2026-10-12T00:00:00+00:00"
  }
}
```

## 想定するフロー

1. ローカル側の送信処理からMakeのCustom webhookへHTTPS POST。
2. `event` と `status` を確認して、確定した日報だけを通す。
3. `event_id` が処理済みなら通知しない（重複防止）。
4. テスト用通知先へ本文を送信する。
5. 成功・失敗の記録と、失敗時の再試行手順を用意する。

ローカルの127.0.0.1へMakeから直接アクセスすることはできません。
ローカルからMakeへ送る方式を想定し、公開トンネルを開く必要はありません。
Webhook URLは秘密情報として環境変数等で管理し、GitHubに保存しないこと。

## 接続後に検証すること

- 正常な通知が1回だけ届く。
- 同じevent_idを再送しても二重に通知されない。
- 送信失敗でも確定済みの日報が失われない。
- 想定外のイベントや下書きは通知されない。

実際に接続・検証した後に、手順、画面、検証日、制約をこの資料へ追記します。
