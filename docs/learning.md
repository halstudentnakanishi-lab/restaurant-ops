# 自分で説明できる作品にする

## 読む順番

1. `samples/sales.csv`：1行が何を表すか説明する。
2. `app/service.py` の `parse_csv`：入力のどこを確認するか、一つずつ試す。
3. `import_csv`：検証・トランザクション・履歴記録を区別する。
4. `summary`：GROUP BYとSUMが返す値を、手計算と照合する。
5. `app/main.py`：APIの入力・戻り値・HTTPエラーを確認する。
6. `static/app.js`：fetch、イベント、DOM更新のつながりを読む。
7. `tests/test_app.py`：一つの不具合をどう再現・検出しているか説明する。

## 自分で行う小さな改善

- 集計に「商品名での絞り込み」を追加し、SQLの条件とテストを変更する。
- ファイル名の表示やエラーメッセージを利用者に伝わる言葉へ改善する。
- 日報の自由記述欄を集計値と分離する。再集計時に何を保持するか設計する。

一度に全部を変更せず、一つの課題につき一つのコミットを残してください。

## 面談前に答えたい質問

- 同じCSVを2回入れたらどうなるか。ファイル名だけ変えたら？
- 全35行のうち1行だけ不正だった場合、DBに何が保存されるか。
- 金額にfloatを使わない理由は？
- 2つの画面で同じ日報を開き、別々に保存した場合は？
- 確定済み日報の日付に売上が追加されたらどうするか。
- SQLiteを選んだ理由と、本番向けに不足しているものは？
- AIが生成したコードを、どのように確認したか。

不明な項目は、コードを確認してサンプルで試してください。「まだ学習中なのでここは説明できない」と区別することも大切です。
